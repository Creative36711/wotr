# BFME2: RotWK — мост для «Войны кольца»

Ремастер «Войны кольца» — отдельное приложение (Tauri). Сами РТС-бои проходят
внутри BFME2:RotWK (закрытый SAGE-движок), поэтому нужен «мост», который:
запускает игру, проходит по меню, настраивает сражение (сложность, фракции,
союзы, цвета, стартовая позиция крепости), генерирует стартовый состав армий
(кольцевая расстановка) и запускает матч.

Этот проект — **рабочий прототип** моста на Python. Его задача — доказать
подход и служить читаемой «спецификацией» для переноса в Rust/Tauri.

**Зависимости:** Python 3 + `numpy` (для визуального детекта готовности).

## Запуск

Требуется Python 3 + `numpy`. Игра должна быть **закрыта** перед запуском
(иначе лаунчер не откроет второй экземпляр).

```bat
:: полный сценарий: опрос -> запуск -> меню -> лобби -> комната -> бой
python main.py

:: остановить после входа в «Лок. сеть»
python main.py --stop-at lan

:: калибровка новой карты (мастер 8 точек)
python tools\calibrate.py
```

## Полный поток (что делает `main.py`)

```
опрос (сложность → игроки → фракция → фракции ботов → карта → роль игрока (защита/атака) → расстановка позиций → армия → герои → WOTR-механики → фора)
  → запись NetworkPref.ini (фракция + авто-цвет игрока + правила)
  → генерация __wotr_generated_presets.big (WOTR-механики + спавн-патч стартовой армии)
  → запуск игры (полный экран)
  → ждать окно game.dat
  → ждать готовность главного меню (визуальный маркер)
    → ЕСЛИ маркер не найден за menu_timeout (60с) → ОШИБКА (вероятно краш)
  → «Сеть» → «Лок. сеть»
    → верификация экрана «Лок. сеть» маркером-картинкой (_tools/Маркер локальной сети.jpg)
    → ЕСЛИ маркер не найден за ~2.5с → клики ушли «в пустоту» (холодный старт),
      повторяем «Сеть» → «Лок. сеть» и сверяемся снова
  → «Создать игру»
  → комната: сложность → фракции → союзы → цвета → фора
  → назначить стартовые позиции на карте (оборона / атака)
  → «Начать игру» → 5-сек отсчёт (ввод заблокирован) → бой
```

Ввод пользователя заблокирован на **всё время** работы сценария (low-level
hooks, пропускающие инжектированный ввод по магическому `dwExtraInfo`).
`Ctrl+Alt+Del` всегда работает — аварийный выход.

## Спавн-патч: `bridge/spawn.py`

### Ростер

73 юнита по 7 фракциям (men: 9, elves: 8, dwarves: 7, isengard: 13,
mordor: 15, goblins: 9, angmar: 12). Полная документация — в
[docs/units_rotwk_2.01.md](docs/units_rotwk_2.01.md).

**Уровни юнитов:**
- `CAP_NONE = 0` — без уровня (11 юнитов: осадные орудия, энты). Аура уровня
  не спавнится.
- `CAP_REGULAR = 5` — обычные отряды (до 5).
- `CAP_HEROIC = 10` — героические/элитные (до 10).

### Кольцевая расстановка

Юниты размещаются **концентрическими кольцами** вокруг центра крепости.
Герои — **линией у ворот** (направление задаётся `gate_angle_deg`).

**Координатная система:**
```
        -Y (вверх на экране)
         |
-X ------+------ +X (вправо)
         |
        +Y (вниз на экране)

Геометрический угол α от +X против часовой стрелки (мат. стандарт).
Y_screen = -R × sin(α) (экранная инверсия).
```

**Параметры:**
| Параметр | Значение | Описание |
|---|---|---|
| `HERO_RADIUS` | 95 | Герои у ворот (зазор от стены ~20) |
| `HERO_SPACING` | 20 | Шаг между героями вдоль касательной |
| `RING1_RADIUS` | 140 | Первое кольцо юнитов |
| `RING_GAP` | 70 | Зазор между кольцами (+70 каждое след.) |
| `MAX_PER_RING` | 8 | Макс. юнитов на кольце |
| `RING_HERO_RADIUS` | 280 | Кольцевой герой (дальнее кольцо) |

**Адаптивное заполнение:** неполное кольцо → шаг автоматически увеличивается
(`360°/N`). Чётные кольца: offset=0°, нечётные: +22.5° (шахматка).

### Формат INI-блока

```ini
; Юнит — с Angle (лицом наружу):
AddModule
    Behavior = ObjectCreationUpgrade ModuleTag_U0
        TriggeredBy  = Upgrade_MenFaction
        ThingToSpawn = GondorFighterHorde
        Offset       = X:140 Y:0 Z:0
        Angle        = 0
    End
End
; Аура — тот же Offset, без Angle:
AddModule
    Behavior = ObjectCreationUpgrade ModuleTag_Ua1
        TriggeredBy  = Upgrade_MenFaction
        ThingToSpawn = WOTR_Aura_GondorForgedBlades
        Offset       = X:140 Y:0 Z:0
    End
End
```

**Теги (глобально уникальны):**
- `ModuleTag_U*` — Ring 1 юниты и ауры
- `ModuleTag_R2*`..`R8*` — Ring 2+ юниты и ауры
- `ModuleTag_H*` — герои
- `ModuleTag_RH*` — кольцевые герои
- `ModuleTag_B*` — юниты ботов
- `ModuleTag_BH*` — герои ботов

### Выходной файл

`__wotr_generated_presets.big` — SAGE-архив (BIGF), содержащий один файл:
`data\ini\object\zzz_wotr\system\zzz_spawn.ini`. Путь настраивается через
`config.json` → `spawn_big` (по умолчанию — `C:\RotWK\__wotr_generated_presets.big`).

> **Внимание:** имя файла и внутренний путь изменились (WOTR Generated Presets):
> было `wotr_generated_presets.big` + `data\ini\object\system\systemwotr_spawn.ini`,
> стало `__wotr_generated_presets.big` + `data\ini\object\zzz_wotr\system\zzz_spawn.ini`.

### WOTR Generated Presets — новые механики

Помимо стартовой армии, файл теперь несёт **новые WOTR-механики**, которые
тоже спавнятся через якорь `WOTRTemporaryVictoryAnchor` (объекты
`WOTR_StartingGold_Player_N`, `WOTR_CommandPointBonus_Player_N`, `SignalFire`,
`WOTR_StartPP_N`, `WOTR_PPRate_N`).

**Порядок объектов в файле:**
1. `WOTR_StartingGold_Player_N` — золото (выше всех);
2. `WOTR_CommandPointBonus_Player_N` — командные очки;
3. `WOTRTemporaryVictoryAnchor` — якорь (спавнит всё остальное).

**Опрос (как и раньше, интерактивный):**
- Вопросы задаются **только игроку** (слот 1); у ботов значения всегда
  **случайные** (для быстрого тестирования).
- В каждом вопросе можно ввести `r` — случайное значение (все оставшиеся
  механики тоже станут случайными).
- Сначала спрашивается: «Задать механики вручную или всё рандомом?» —
  `2` = всё рандом.

**Вопросы игроку (слот 1):**

| # | Вопрос | Результат в файле |
|---|---|---|
| 1 | Сколько бонусных стартовых денег у игрока? (0 = без, Enter = 5000) | Базовый `Object WOTR_StartingGold` (полный код, один раз) + `ChildObject WOTR_StartingGold_Player_1` с `ReplaceModule` (`MinResource = MaxResource = <ответ>`, рандома нет) + модуль `ModuleTag_Gold_1` в якоре |
| 2 | Сколько дополнительных командных очков у игрока? (0 = без, Enter = 500) | `ChildObject WOTR_CommandPointBonus_Player_1 WOTR_CommandPointBonus` → `CommandPointBonus = <ответ>` + модуль `ModuleTag_CP_1` |
| 3 | Есть ли у фракции игрока сигнальный огонь? (`1` = да, Enter = да, `нет`/`0` = нет) | При «да»: модуль `ModuleTag_SignalFire_1` → `ThingToSpawn = SignalFire`, `Offset = X:9999 Y:9999 Z:0` (за картой — невидим, бонус работает). При «нет» блок не генерируется |
| 4 | Сколько стартовых PP у игрока? (0–10, Enter = 5) | Модуль `ModuleTag_StartPP_1` → `ThingToSpawn = WOTR_StartPP_<ответ>` |
| 5 | Сколько PP получает игрок каждые 2 минуты? (1–5, Enter = 3) | Модуль `ModuleTag_PPRate_1` → `ThingToSpawn = WOTR_PPRate_<ответ>` |

**Структура генерируемого файла (схема):**

```ini
; ============================================================
; WOTR Generated Presets
; Путь: data\ini\object\zzz_wotr\system\zzz_spawn.ini
; ВНИМАНИЕ: файл генерируется автоматически, не редактировать
; ============================================================

; --- Стартовое золото: базовый объект + дочерние (все игроки) ---
Object WOTR_StartingGold                       ; полный рабочий код (один раз)
  Draw = W3DScriptedModelDraw ModuleTag_01
    DefaultModelConditionState
      Model = PchestTreasure
      ParticleSysBone NONE GoldChestGlimmer
      ; ... GoldChestGlimmer02 / Red / Green / Aura ...
    End
  End
  KindOf = SELECTABLE PARACHUTABLE IMMOBILE NOT_AUTOACQUIRABLE UNATTACKABLE CRATE
  Behavior = SalvageCrateCollide ModuleTag_02   ; базовые значения (для «диких» сундуков)
    ForbiddenKindOf = PROJECTILE ENVIRONMENT IGNORED_IN_GUI
    ExecuteFX = FX_GoldChestPickup
    ResourceChance = 20%    ; MinResource = 25, MaxResource = 75 и т.д.
    AllowAIPickup = No
  End
  Behavior = DeletionUpdate ModuleTag_03        ; сундук исчезает через 30–35с
    MinLifetime = 30000
    MaxLifetime = 35000
  End
  ; ...
End

ChildObject WOTR_StartingGold_Player_1 WOTR_StartingGold
    ReplaceModule ModuleTag_02                  ; 100% шанс, сумма = ответ
        Behavior = SalvageCrateCollide ModuleTag_022
            ForbiddenKindOf = PROJECTILE ENVIRONMENT IGNORED_IN_GUI NEUTRALGOLLUM
            BannerChance = 0%
            LevelUpChance = 0%
            LevelUpRadius = 0.0
            ResourceChance = 100%
            MinResource = 7000                  ; рандома нет, Min = Max
            MaxResource = 7000
            AllowAIPickup = Yes
            ExecuteFX = FX_GoldChestPickup
        End
    End
    ReplaceModule ModuleTag_03                  ; сундук НЕ исчезает
        Behavior = DeletionUpdate ModuleTag_033
            MinLifetime = -1
            MaxLifetime = -1
        End
    End
End
; ... (ChildObject WOTR_StartingGold_Player_2..8 по числу слотов)

; --- Командные очки (все игроки) ---
ChildObject WOTR_CommandPointBonus_Player_1 WOTR_CommandPointBonus
    CommandPointBonus = 800
End
; ...

; --- Якорь (спавн всего) ---
Object WOTRTemporaryVictoryAnchor
    ; Золото / ОК / огонь / старт. PP / прирост PP — на каждый слот
    AddModule
        Behavior = ObjectCreationUpgrade ModuleTag_Gold_1
            TriggeredBy  = Upgrade_MenFaction
            ThingToSpawn = WOTR_StartingGold_Player_1
            Offset       = X:0 Y:0 Z:0
        End
    End
    ; ... ModuleTag_CP_N / ModuleTag_SignalFire_N (X:9999 Y:9999 Z:0) /
    ;     ModuleTag_StartPP_N (WOTR_StartPP_<N>) / ModuleTag_PPRate_N ...

    ; --- Стартовая армия (кольцевая расстановка) — «всё остальное» ---
    AddModule ... End
End
```

**Маппинг фракций → апгрейды (TriggeredBy):**

| Фракция | TriggeredBy |
|---|---|
| Men | `Upgrade_MenFaction` |
| Elves | `Upgrade_ElfFaction` |
| Dwarves | `Upgrade_DwarfFaction` |
| Isengard | `Upgrade_IsengardFaction` |
| Mordor | `Upgrade_MordorFaction` |
| Wild (Гоблины) | `Upgrade_WildFaction` |
| Angmar | `Upgrade_AngmarFaction` |
| Arnor | `Upgrade_ArnorFaction` |

Диапазоны случайных значений (боты / режим `r`): золото 500–10000,
ОК 100–1000, старт. PP 0–10, прирост PP 1–5, сигнальный огонь — 50/50
(константы `MECH_*_RANGE`, `SIGNAL_FIRE_CHANCE` в `bridge/spawn.py`).

Стартовая армия (кольцевая расстановка юнитов/героев/аур) остаётся в том же
файле — её модули добавляются в якорь после модулей механик.

## Детект готовности экрана — `bridge/visual_ready.py`

Таймеры и CPU/диск ненадёжны (анимированный фон меню, кэш ОС). Надёжный способ —
**визуальный маркер**: у кнопок с выпадающим списком есть маленький
треугольник-индикатор, который не меняется между модами и локализациями.

**Если маркер не найден за `menu_timeout` (60 сек) — процесс останавливается
с ошибкой** (вероятно, игра крашнулась или зависла).

Как задать маркер (один раз):

1. Запусти `python tools\calibrate.py --free` (UAC — «Да»).
2. Дождись главного меню игры.
3. Alt-Tab в игру, наведи курсор на треугольник над кнопкой «Сеть» → **F8**.
4. Сохранится `config/menu_marker.npy` + `config/menu_marker.json`.

### Маркеры-картинки (JPG) — верификация экранов

Кроме «квадратного» маркера из калибратора поддерживаются **маркеры-картинки**:
обычные .jpg-вырезки нужного элемента экрана (лежат в `_tools/` рядом с
приложением). Они ищутся **нормализованной кросс-корреляцией (NCC)** по кадру
(или по зоне в долях окна) и автомасштабируются под текущее разрешение —
точную позицию элемента знать не нужно.

- `_tools/Маркер локальной сети.jpg` — маркер экрана «Лок. сеть». Используется
  в `main.py` сразу после клика «Лок. сеть»: если маркер найден за
  `lan_marker_timeout` (~2.5с) — идём дальше; если нет — клики ушли «в
  пустоту» (холодный старт, игра ещё не принимала ввод), навигация
  «Сеть» → «Лок. сеть» повторяется и проверяется снова. Если главное меню при
  этом НЕ подтверждено маркером меню — просто ждём ещё (экран грузится).
- `_tools/Маркер статистики.jpg` — маркер экрана «Статистика» (для пост-боевого
  анализа; см. `match_result_detector`).

Зоны поиска — `LAN_SCREEN_MARKER_ROI` / `STATS_SCREEN_MARKER_ROI` в
`bridge/visual_ready.py`, порог `IMAGE_MARKER_THRESHOLD = 0.85` (на своём экране
маркер даёт NCC ~0.999, на чужих ≤0.73). Функции: `load_marker_image`,
`is_image_marker_visible`, `wait_image_marker`.

## Калибровка карт и маркеров — `tools/calibrate.py`

Инструмент калибровки позволяет добавлять новые карты в игру за пару минут.

Запуск:
```bat
python tools\calibrate.py
```

### Как работает мастер добавления карты:
1. При запуске спрашивает название карты (например, `Хельмова Падь`) и системное имя (`map mp ...`).
2. Спрашивает тип: **Крепость** или **Обычная карта**.
3. Запускает игру в окне (понижает разрешение до 1280×720 и восстанавливает).
4. Ведёт пользователя по 8 точкам на миникарте (наводим курсор и жмём **F9**):
   - **Для крепости:**
     - 1-я точка: **ГЛАВНАЯ позиция владельца крепости** (управляет воротами крепости);
     - 2..4 точки: позиции обороны;
     - 5..8 точки: позиции атаки (по приоритету).
   - **Для обычной карты:**
     - 1..4 точки: позиции обороны (по приоритету);
     - 5..8 точки: позиции атаки (по приоритету).
5. После 8-го нажатия F9 карта **автоматически сохраняется в `config/maps.json`** и сразу становится доступна в `main.py`!

Горячие клавиши:
- **F8** — захватить маркер готовности вокруг курсора → `config/menu_marker.*`;
- **F9** — зафиксировать текущую точку карты (шаги 1..8);
- **F10** — выход / отмена.

## Пост-бой: защита от преждевременного клика «Пропустить»

После боя экран статистики открывается на «Войсках» с анимацией вкладок.
Чтобы не ждать ~15с отрисовки, автоматизация жмёт **«Пропустить»** (кнопка
внизу справа, frac `(0.9109, 0.9583)`). Проблема: пользователь может успеть
нажать «Пропустить» **до** блокировки ввода, анимация закончится, и наш клик
в ту же точку попадёт уже по **«Далее»** — мы улетаем на экран «Статистика»,
а анализировать нужно график.

Решение — **A+B** (`match_result_detector`):

- **A. Ранняя блокировка ввода**: `monitor_poll = 0.25с`, `confirm_streak = 1`
  (fortress_icon на статистике NCC ~1.0, на лобби ~0.57 при пороге 0.85 —
  ложных срабатываний нет). Ввод блокируется через ~0.3с вместо 1–1.5с.
- **B. Сторожевой цикл в `_analyze_score_screen`**: перед каждым шагом и на
  каждой итерации ожидания кадра проверяется маркер «Статистики»
  (`_tools/Маркер статистики.jpg`, NCC 0.999 против ≤0.73 на графике). Если мы
  на «Статистике» — жмём **«Назад»** (frac `(0.0883, 0.9556)`) и возвращаемся
  на график; график подтверждается по `is_score_screen` (fortress_icon +
  score_screen_marker) перед анализом. «Пропустить» по-прежнему жмём — так
  быстрее, а ошибочный переход всегда откатывается.

Кнопки/маркеры настраиваются в `match_result_detector/config.py`:
`stats_marker_path`, `stats_marker_roi`, `stats_marker_threshold`,
`back_button_frac`, `monitor_poll`, `confirm_streak`.

## Настройки — `bridge/network_prefs.py`

Файл `%APPDATA%\My Rise of the Witch-king Files\NetworkPref.ini` готовится
**до запуска игры** (она читает его при старте и перезаписывает при выходе).

### APPDATA и UAC-повышение

**Проблема:** при `elevate.ensure_admin()` скрипт перезапускается от имени
администратора. Переменная `%APPDATA%` после UAC может указывать на **другой
профиль** (Administrator), а не на профиль реального пользователя. Это
приводило к тому, что скрипт не мог найти или создать `NetworkPref.ini` в
правильной папке (подтверждено на машинах с нелатинскими именами пользователей).

**Решение (4-уровневый fallback):**
1. `_REAL_APPDATA` — сохраняется `main.py` **до** `elevate` и передаётся
   повышенному процессу через аргумент `--_real_appdata=<путь>`.
2. `SHGetKnownFolderPath(FOLDERID_RoamingAppData)` — Win32 API, всегда
   возвращает путь текущего пользователя.
3. `%APPDATA%` — переменная окружения (может быть неверной после UAC).
4. Сканирование `C:\Users\*\AppData\Roaming\My Rise of the Witch-king Files\`
   — ищет папку с `NetworkPref.ini` или `Options.ini`.

## Карты и стартовые позиции — `bridge/maps.py`

Вместо старого разделения на «крепость / обычная локация» программа всегда
спрашивает, на какой карте проходит игра, и кем является игрок (защитник или
атакующий).

### Доступные карты
1. **Вестмарш** (`map mp tournament westmarch`) — обычная карта
2. **Дагорлад** (`map wor dagorlad`) — обычная карта
3. **Мёртвые топи** (`map wor dead marshes`) — обычная карта
4. **Минас Тирит** (`map wor minas tirith`) — **крепость** (`is_fortress: True`)

На каждой карте задано фиксировано **8 точек**:
- **4 позиции обороны** (первые 4 точки, отсортированы по приоритету);
- **4 позиции атаки** (следующие 4 точки, отсортированы по приоритету).

Поддерживаются любые форматы боёв: 1х1, 1х3, 2х2, 3х3, 4х4 и асимметричные составы.

### Карты-крепости и владелец крепости
Если выбранная карта является крепостью (Минас Тирит), программа спрашивает:
**«Кто владелец крепости (из защитников)?»**
- Выбирается один из слотов защиты (например, слот 1, 2, 4 или 8).
- Выбранный слот гарантированно встаёт на **самую первую координату обороны** (`defense_positions[0]`).
- Оставшиеся защитники распределяются по оставшимся точкам обороны (по приоритету или случайно).

### Режимы расстановки
- **По приоритету** (по умолчанию):
  - $N$ слотов защиты получают первые $N$ точек обороны из списка (для крепости: 1-я точка — владельцу крепости, остальные — по списку);
  - $M$ слотов атаки получают первые $M$ точек атаки из списка.
- **Случайно**:
  - Для крепости: владелец крепости всегда на 1-й точке обороны, остальные защитники получают случайные точки из оставшихся оборонительных;
  - $M$ слотов атаки получают $M$ случайных точек из 4 атакующих.
  - Защитники и атакующие разделены: защитник никогда случайно не окажется на позиции атаки, и наоборот.

### Механика назначения позиций в комнате
В комнате BFME2 клик по свободной точке на миникарте автоматически назначает
**следующий свободный слот**:
- **Если карта — крепость с владельцем (слот $K$):**
  1. Первым назначается владелец крепости: кликаем по 1-й точке обороны $K$ раз (1 клик = слот 1, 2 = слот 2, ... $K$ кликов = слот $K$). Точка закрепляется за слотом $K$.
  2. Все остальные слоты назначаются последовательно по возрастанию номеров ($1, 2, 3, \dots$) ровно по **1 клику** на свою точку (игра автоматически подставляет следующий свободный номер).
- **На обычной карте (без крепости):**
  Все слоты назначаются последовательно по возрастанию номеров ($1, 2, 3, \dots$) ровно по **1 клику** на каждую позицию.

## Важные правила (переносятся в Tauri-версию)

1. **Игра в полноэкранном режиме** (без `-win`). Оконный режим ломал камеру в
   бою (edge-scroll). Клики меню работают и в полноэкранном режиме через
   SendInput (проверено).
2. **Скрипт/приложение — от админа.** Игра запущена elevated, и Windows (UIPI)
   блокирует ввод из непривилегированного процесса.
3. **Окно ищем только по `game.dat`**, не по лаунчеру (`lotrbfme2ep1.exe`
   появляется раньше со скрытым окном).
4. **Навигация по координатам (долям окна), а не по тексту** — не зависит от
   языка и мода. Для детекта «экран загрузился» — визуальный маркер.
5. **Перед запуском игра должна быть закрыта** — иначе второй экземпляр не
   откроется.
6. **Цвет игрока исчезает из списков ботов**; цвета, занятые ботами, остаются
   в списке, но клик по занятому отберёт его у владельца → повторным фракциям
   оставляем «Случайный» цвет.
7. **Таймаут маркера = ошибка.** Если маркер главного меню не найден за
   `menu_timeout` (60 сек), процесс останавливается — вероятно, игра крашнулась.
